# Выпуск физической карты новым пользователем

Сценарий (`SequentialTaskSet`): создание пользователя → открытие дебетового счёта → выпуск физической карты.

Запуск из корня проекта:

```bash
locust --config=./scenarios/http/gateway/new_user_issue_physical_card/v1.0.conf
```

## Профиль нагрузки

`users = 30`, `spawn-rate = 3`, `run-time = 3m`, headless.

- Флоу популярный, но не пиковый: новые пользователи приходят постоянно, но без массового наплыва,
  поэтому нужна умеренная нагрузка, а не стресс.
- Для такого же флоу нового пользователя в уроке взято 100 пользователей. Стенд здесь работает на
  машине с 2 vCPU, и на пробном прогоне со 100 пользователями он упёрся в CPU (≈197 % из 200 %,
  медиана open-debit-card-account ≈ 6,8 с, Locust предупредил о высокой загрузке CPU).
  Поэтому нагрузка уменьшена до 30 пользователей: так система загружена, но не перегружена
  (≈120 % CPU суммарно по контейнерам стенда), а задержки соответствуют уроку.
- `spawn-rate = 3`: все пользователи стартуют плавно, примерно за 10 секунд, как в уроке (100 / 10).

Прогон: 30.09.2026 22:02:26–22:05:26 UTC. В report.html время показывается в часовом поясе браузера, на скриншотах Grafana — в UTC.

| POST /api/v1/cards/issue-physical-card | 783 | 0 | 120 | 290 | 930 |
| **Aggregated** | **2382** | **0** | 130 | 580 | 1100 |

- Fails = 0, RPS в среднем ≈ 13,2. Каждая из трёх задач выполнялась примерно одинаково часто:
  у SequentialTaskSet шаги идут строго по очереди.
- Самый тяжёлый шаг — открытие дебетового счёта: при нём создаётся счёт и сразу выпускается карта.
  Выпуск физической карты заметно легче (p95 ≈ 290 мс).
